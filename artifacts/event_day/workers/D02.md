## Assumptions and decisions

- **MCP registration is not via `nemoclaw mcp add`.** It requires an HTTPS URL and rejects
  `host.openshell.internal`, and a TLS proxy was out of the time budget. D01's registration is merged
  into `openclaw.json` using the procedure NemoClaw documents (`docs/inference/set-up-sub-agent.mdx`),
  and egress is enforced by a custom OpenShell preset.
- **Bearer token is literal in the sandbox `openclaw.json`.** The NemoClaw-started gateway has no
  `AUM_TOOLS_TOKEN` env var, so the `${AUM_TOOLS_TOKEN}` reference would not resolve. The file is 0600
  (sandbox user) and the agent denies `group:fs`/`group:runtime`. The token is never in the repo,
  artifacts or argv; a grep of artifacts and the new files for the token found nothing.
- The OpenClaw MCP client also tries `GET /mcp` (SSE stream). The preset denies it at L7, as the
  gateway log shows (`policy_denied`). The server only answers 405 there anyway, and tool calls are
  unaffected.
- Cosmos :8001 is published on loopback only (not on 172.18.0.1 as the addendum says). The reasoning
  call is made host-side by the tool server, so the sandbox does not need it.
- Telegram stays deferred. No channel, egress or `message` tool. The API still emits
  `alert.delivery {channel: telegram, status: not_connected}` (apps/api code, not D02's). Hiding it in
  the UI is apps/web work, which D02 may not edit.
