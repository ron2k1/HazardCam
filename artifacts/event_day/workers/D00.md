## Design summary

- **Agent.** `urban-mirror`. The brain is `inference/nvidia/Qwen3.6-35B-A3B-NVFP4` through OpenShell `inference.local` (local vLLM :8000), with no fallbacks. Thinking, memory search, skills, subagents and heartbeat are off. Loop detection is on (3/5/8).
- **Least privilege.** Profile `minimal`, with `session_status` denied. Every tool group except `group:messaging` is denied. `alsoAllow: ["message"]`, `tools.message.actions.allow: ["send"]`, cross-context sends off, broadcast off. D01 adds its tool surface id to `alsoAllow`.
- **Policy.** Only the 7 contract tools; visible cameras only (a refusal never echoes the rejected id); per-tool, per-camera and total caps plus a deadline; closed after submit; a submitted claim may only weaken the reasoner's.
- **Abstention.** Floor 0.3. A rival ranked at or above the claim forces an abstention. Missing or close alternatives become limitations. An abstention keeps the claim as an alternative. `finalize()` abstains for an agent that never submitted.
- **Telegram alert.**
  - **When:** after a successful submit whose gated hypothesis is a known `EVENT_TYPES` event at ≥ 0.3. Not for `unknown` or `no_event`.
  - **Text:** composed by the policy (event, confidence, coarse region, cited visible cameras with their scenario-time spans, run id) and checked for URLs and token shapes.
  - **Handoff:** returned as `alert` next to the contract result. `authorize_alert` grants one `send` and always substitutes the policy's own arguments.
  - **Outcome:** `record_alert` gives `sent`, or `skipped` with a redacted reason. It never changes the hypothesis, the run or the SSE stream.
  - **No delay:** the run closes at the submit (`wait_closed`), so `run.complete` never waits for Telegram.
  - **Secrets:** the bot token never reaches this code. `AlertRoute` rejects token-shaped targets.

## Assumptions

- **OpenClaw version.** The agent is written for OpenClaw 2026.7.1, the version inside the sandbox (runtime pitfall P1). If D02 recreates the sandbox on another version, revalidate `agent.json` with `openclaw config validate`.
- **Tool names.** D01 exposes the seven tools under their contract names. If its surface adds a prefix (an MCP server prefix, for example), D01 updates the names in `AGENTS.md`.
- **Alert target.** The Telegram chat id (or `@channel`) comes from operator configuration at run time (an env var D02 chooses). It is not a secret, but it stays out of repo files and out of `summary()`.
- **SSE.** The alert outcome is not an SSE event: the stream closes at `run.complete`. D02 decides how the UI shows "skipped" (from `alert_summary()` via the listener or a run artifact).
