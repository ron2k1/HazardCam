# P13 worker report: fixture browser E2E gate

Status: done. Date: 2026-10-02.

## Command

From the repo root, with one command:

```
pnpm --dir apps/web e2e                                              # fixture (default)
E2E_PROFILE=lite-local E2E_RUN_TIMEOUT_S=600 pnpm --dir apps/web e2e  # P14: real local models
```

Suggested `scripts/run.sh` wiring. Both are one line, and `"$@"` passes Playwright arguments through, e.g. `-g eval_001`:

```
  fixture-e2e) pnpm --dir apps/web e2e "$@" ;;
  lite-e2e) E2E_PROFILE=lite-local E2E_RUN_TIMEOUT_S="${E2E_RUN_TIMEOUT_S:-600}" pnpm --dir apps/web e2e "$@" ;;
```

The PowerShell equivalent of the lite line is `$env:E2E_PROFILE='lite-local'; $env:E2E_RUN_TIMEOUT_S='600'; pnpm --dir apps/web e2e`. See "Profile and run budget" below.

`pnpm --dir apps/web e2e` runs `playwright test -c ../../tests/e2e/playwright.config.ts`, using `@playwright/test` 1.63.0 from apps/web devDependencies and its bundled Chromium. The config's `webServer` block starts both servers and stops them by PID tree (Playwright runs `taskkill /pid <pid> /T /F` on Windows):

- **api.** `.venv` python `-m uvicorn apps.api.main:app` on 127.0.0.1:8080, with `MODEL_PROFILE=$E2E_PROFILE` (default `fixture`). Runs are written to `%TEMP%/ambient-mirror-e2e-runs`, not `data/runs`.
- **web.** `next build && next start` on 127.0.0.1:3000, with `NEXT_PUBLIC_API_BASE_URL` set to the api.

Env knobs, documented in `tests/e2e/README.md`:

- `E2E_PROFILE` (default `fixture`) and `E2E_RUN_TIMEOUT_S` (default 60)
- `E2E_API_PORT`, `E2E_WEB_PORT`
- `E2E_REUSE_SERVERS=1`. The default is fresh servers, so a foreign process on the port fails the run instead of being tested.
- `E2E_SKIP_BUILD=1`
- `E2E_PYTHON`

4. **API down.** All requests to the API are aborted in the browser. Result: OFFLINE alert, RUN and select disabled, health API row `offline`, GT withheld. Once the API is back, the page recovers to online, scenarios load and RUN is enabled.

## Profile and run budget (additive requirement, for P14)

- **`E2E_PROFILE`** (default `fixture`) is the `RunRequest.profile` of the eval_001 test.
  - The config starts the API with `MODEL_PROFILE=$E2E_PROFILE`, because /ops offers only fixture plus the API's default profile.
  - The test chooses the profile in the PROFILE select, and asserts both `POST /api/runs` and the run record carry it.
  - The profile name must match the API's profile-name rule and have `config/models/<profile>.yaml`. Otherwise the suite stops before any server starts. A typo never falls back to fixture, so a fixture pass can never be reported as a real-model pass.
- **`E2E_RUN_TIMEOUT_S`** (default 60, the fixture budget) bounds the wait from the RUN click to the terminal phase. The per-test timeout is that budget plus 60 s. A run that ends `failed` stops the wait at once and fails with its banner text. An invalid value stops the suite.
- **Assertions under a non-fixture profile.**
  - Kept:
    - the 7-tool trace (rows equal the server event log, including each call's ok or error outcome, and the distinct tools follow the harness order);
    - the timeline evidence seek;
    - GT withheld until REVEAL, with no judge request before it;
    - the run finishing within budget;
    - the hypothesis readouts equal to the server record;
    - the 390 px layout and no console errors.
  - Health must read `ok` on the PROFILE row, meaning every model endpoint answered `/models`, instead of `fixture`.
  - Not asserted for real models (fixture only): the recorded eval_001 hypothesis is a claim, it cites evidence besides the latest bar (so the chip seek always runs), and no tool failed.
  - The chip seek still runs whenever the real hypothesis cites timeline evidence.
- **The other tests stay on fixture under any profile.** eval_012 and eval_005 check recorded outcomes. The resilience tests need a fixed event log. Their titles say `[fixture]`, and they post `profile: fixture`, which the API accepts whatever its default.
- **Artifacts of a non-fixture run** are named by profile, so they never overwrite the fixture set:
  - `ops-<profile>-eval_001-desktop.png`, `-revealed-desktop.png` and `-narrow-390.png`
  - `<profile>-run-timing.json`, which adds the hypothesis summary and the failed-call count
  - `results-<profile>.json`

  The fixture-pinned tests rewrite their own fixture screenshots.
- **Lite-local prerequisites.** None of these were run here.
  - Ollama is up on 127.0.0.1:11434 with the lite-local tags warm. `artifacts/model/MODEL_BENCHMARK.md` explains how to check `/api/ps` before a judged run.
  - The PROFILE health row must read `ok`. That health check is a cheap `GET /v1/models` and loads no model.
- **Why 600 s for lite.** It is a suggestion; the docs give no lite-local run target. The benchmark measured full-local scenarios at a median of 77.2 s and a maximum of 177.4 s on a shared GPU. `lite-local.yaml` allows 180 s per model call with 2 retries. Override it with `E2E_RUN_TIMEOUT_S`.

- **Seq guard removed** from `applyEvent`: test 6 failed, with `replayed_duplicate=true` rendered in the trace. The trace still read `12 CALLS`, so without the marker the replay test would have passed vacuously; that is why it carries one.

## Findings while building the gate

- **`Last-Event-ID` is invisible to Playwright on intercepted requests.** `route.request().headers()` and `allHeaders()` omit it, although Chromium sends it. I checked with a standalone probe server, same-origin and cross-origin, which received `10` and then `20`, and with CDP `Network.requestWillBeSentExtraInfo`. Test 5 therefore reads the wire through CDP.
- **A vacuous confidence check, now fixed.** The eval_012 check used panel-wide `toContainText("0.61")`, which matched the reason prose ("cluster score (0.6177)"). The screenshot had caught the `NumberTicker` spring mid-settle at "0.60". The server value is 0.61; `hypothesis.json` and `hypothesis.raw.json` agree. Assertions now target exact readouts with `toHaveText`, which also waits for the settle.

## Assumptions

- **Run-time target.** The docs state none, so the default budget is 60 s (`E2E_RUN_TIMEOUT_S`, `tests/e2e/env.ts`). The 600 s lite budget is a suggestion too (see "Profile and run budget").
- **Injected failure.** Test 7 is UI-only and labelled so in its title. The fixture backend cannot produce a failed tool on demand without Python changes.
- **Replay.** Test 6 simulates a resume source that ignores `Last-Event-ID`; the real API honours it (test 5).
- **Chromium only**, the bundled build 153, which plays the scenario H.264 mp4s.
