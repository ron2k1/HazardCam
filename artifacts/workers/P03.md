### `PublicScenario` fields

- `id`, `title`, `duration_seconds`, `coordinate_frame`
- `cameras[]`: `id`, `label`, `position`, `heading_deg`, `fov_deg`, `time_offset_s`, `media_url`, `media_available`
- `zones`
- `has_ground_truth: true`
- `provenance`: always an object; only whitelisted keys with string values (`kind`, `source`, `dataset`, `dataset_url`, `url`, `source_url`, `license`, `license_url`, `attribution`, `citation`, `note`), possibly `{}`

The view never includes a camera `file`. It is passed through the GT redactor, so the GT id, path and basename never appear (each is replaced by `[withheld]`).

### SSE

- Each message is `id: <seq>` plus `data: <envelope json>`, with no `event:` field. The envelope is `{seq, type, ts, run_id, payload}`; `ts` is UTC ISO with ms and `Z`.
- `seq` starts at 1 and is contiguous. It is assigned under one lock, together with the `events.jsonl` write and the `call_soon_threadsafe` hand-off, so executor threads cannot reorder it.
- A stream replays everything after `max(after_seq, Last-Event-ID)`, then follows live events. It closes after `run.complete` or `run.failed`.
- A finished run is a pure replay and closes immediately.
- Keepalive pings (`: ping` comments) are sent every `AUM_SSE_PING_S`, default 15 s.

### Persistence

- Each run is persisted to `data/runs/<run_id>/run.json` (rewritten on every state change) and `events.jsonl` (append-only).
- `run_id` has the form `run_YYYYMMDDTHHMMSSZ_<6 hex>`.

## Executor contract (for P10)

- **Install:** `app.state.executor = callable`. It is called positionally in a worker thread as `executor(scenario: Scenario, profile_name: str, emit, run_dir: Path, pace_s: float) -> Hypothesis`.
  - P10's `run_dev_sequence(scenario, load_profile(name), emit, run_dir=..., pace_s=...)` needs a thin wrapper, because the API passes the profile *name*, not a loaded `ModelProfile`.
- **`emit(type, payload)`:**
  - It is thread-safe, and the payload may contain pydantic models.
  - It raises `ValueError` for `run.complete`/`run.failed` (the API emits those), an unknown type, or NaN/inf.
  - It raises `TypeError` for a non-dict payload.
  - It raises `GroundTruthAccessError` if the payload mentions the GT camera id, path or basename. No seq is spent on a refused event.
  - `tool.started {tool}` updates the run's failure stage.
- **On return:** the Hypothesis is re-validated, and `run.complete {hypothesis, duration_ms}` is emitted. A hypothesis that cites the GT camera fails the run.
- **On exception:** `run.failed {stage, error}` is emitted, with state `failed`.
  - `stage` is `exc.stage` if the exception carries one, else the last `tool.started` tool, else `startup`.
  - `error` is one line, `Type: message`, at most 300 chars, with no traceback and GT tokens redacted. The server log gets the exception type only (traceback at DEBUG).
- **Frames:**
  - Write frames to `<run_dir>/frames/<camera_id>/<index:04d>.jpg`. This matches P04's `sample_video(out_dir=run_dir / "frames")` layout.
  - Put URLs in events with `apps.api.services.media.frame_url(run_id, camera_id, index)`, which gives `/media/runs/{run_id}/frames/{camera_id}/{index}.jpg`. The route accepts both `3.jpg` and `0003.jpg`.

## Frontend notes (for P11)

- Base URL: `http://127.0.0.1:8080`. CORS allows `http://127.0.0.1:3000` and `http://localhost:3000`.
- Visible camera video: `camera.media_url` from the scenario (`/media/scenarios/{id}/cameras/{camera_id}`). It supports Range, so `<video>` seeking works.
- Start a run by POSTing `{scenario_id}` to `/api/runs`, then open `new EventSource(events_url)`.
  - The browser's automatic reconnect sends `Last-Event-ID`, and the server resumes after it.
  - `onmessage` only, since there are no named events. Parse `JSON.parse(e.data).type`.
- Judge view: `/api/judge/scenarios/{id}` and its `/video`. These are the only routes that expose the GT camera.

## Assumptions

- `GET /api/scenarios` wraps the list as `{"scenarios": [...]}`, which leaves room for metadata later.
- Camera `file` paths resolve against `AUM_MEDIA_ROOT` (default: the repo root). An absolute `file` is used as-is.
- `expected.json` is read from `<AUM_PREPARED_DIR>/<scenario_id>/expected.json`.
- The scenario store reloads when the manifest set (name, mtime, size) changes. Invalid manifests and duplicate ids are skipped with a warning and listed in `/healthz` as `invalid_manifests`. `*.provenance.json` files are not scenarios.
- Runs are in memory. After a restart, `GET /api/runs/{id}` returns 404. The frames route still serves files by reading `run.json` for its GT check.
- **Models health:**
  - It uses `inference.profiles.load_profile(name, require_resolved=False)` (P06) only when `models_dir` is P06's own `config/models`. Otherwise it reads the yaml directly.
  - Both paths apply the `QWEN_*`/`MISTRAL_*` overrides.
  - A role with an unset or `REPLACE*` `base_url` or `model` is reported as `unconfigured` with a `missing` list, and is not probed. This matches P06's selection rule, so `gb10` reports unconfigured until its env is set, instead of a misleading `ok`.
  - Probes use `trust_env=False`, a 2 s timeout, and no credentials. Any userinfo is stripped from the reported URLs.

## Deviations from the plan's interfaces

- **Temporary executor:**
  - It reports `harness: "fixture-replay"`.
  - Its `camera.frames.sampled` events carry `frames: []`, since it reads no video.
  - It reads `data/fixtures/<scenario_id>/` before `data/fixtures/`.
- **POST /api/runs** adds `run_url` and `events_url` to the `RunRecord` fields and sets the `Location` header. GET returns the same shape.
- **Extra env settings:**
  - `AUM_MEDIA_ROOT`, `AUM_MODELS_DIR`
  - `AUM_SSE_PING_S` (15)
  - `AUM_CORS_ORIGINS` (comma-separated)
  - `AUM_DEFAULT_PACE_S` (default **0.0**; capped at 5)
- `/healthz` reports `degraded` (not an HTTP error) when a dependency fails, and always returns 200.
