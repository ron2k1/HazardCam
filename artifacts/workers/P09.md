## Behaviour

- **Input.** The model receives ONLY the system prompt and a user turn made of the compact bundle JSON (`exclude_none`) plus lines derived from it: bundle status, valid evidence ids, and valid region values. A test asserts the user message equals `bundle_message(bundle)` exactly.
- **Schema.** A per-bundle `response_format` json_schema with `reason` first (justification before the label). The `evidence_ids` enum is the bundle ids (maxItems 0 when empty); `event_type` enum, `region` enum (candidate ids + `unknown`), at most 3 alternatives, and at least 1 limitation.
- **Post-validation.**
  - Unwraps `{"hypothesis": {...}}`.
  - Normalizes event_type; an unrecognized type becomes `unknown` plus a limitation.
  - Region: a candidate id, or a match by label or case. Otherwise it becomes `unknown` plus a limitation.
  - Unknown or malformed evidence ids are dropped and counted, with a limitation.
  - Confidence is rescaled and clamped (92 becomes 0.92).
  - Alternatives are normalized and deduped (max confidence), exclude the main type, are sorted descending and capped at 3.
  - Markdown emphasis is stripped from reason and limitations (ministral bolds ids).
  - `NOT_DIRECTLY_VISIBLE` (identical to `tools.submit`) is always present.
- **Abstain paths.**
  - Empty evidence: abstain with no model call.
  - Invalid output: one conversational repair (system, user, the bad assistant reply, a correction).
  - A second failure or a ModelCallError: a schema-valid `unknown@unknown`, conf 0.0, with the failure in `limitations` and `CallInfo.ok=False`. `strict=True` raises.
  - Context overflow is warned and added as a limitation.
- **Division of labour with P08's gate.** The confidence caps (0.35 insufficient, 0.6 single camera) and the no-evidence downgrade live in `tools.submit.submit_hypothesis`. They are not duplicated here.
  - The prompt states the same numbers; `test_prompts` pins them to `tools.submit` constants.
  - Tests prove that a well-formed adapter output is a fixed point of the gate, that an abstention on an insufficient bundle survives the gate unchanged, and that an overconfident claim on an insufficient bundle is capped by the gate to 0.35.

## Event vocabulary realigned to the real scenarios (interface change)

The first vocabulary was incident-oriented (collision, smoke_or_fire, ...). None of its names appears in any prepared `expected.json`, so no positive could ever score. The vocabulary is now the judge-facing coarse classes that P05's scripts write (`find_candidates.COARSE_CLASS` / `prepare_scenario.ACCEPTED`), plus `unknown` and `no_event`:

`passenger_dropoff_pickup, vehicle_turnaround, vehicle_stop, vehicle_departure, vehicle_turn, vehicle_loading_unloading, object_transport, object_left_behind, object_taken, cyclist_movement`

Synonyms map in code, for example:
- `u_turn` / `vehicle_reversing` / `vehicle_maneuver` become `vehicle_turnaround`
- `stopped_vehicle` / `traffic_obstruction` become `vehicle_stop`
- `vehicle_starts` becomes `vehicle_departure`
- MEVA activity names map to their coarse class

`test_vocab` reads every `data/prepared/*/expected.json` (22 today; the test skips when none exist) and asserts three things:
- the main label is in the vocabulary (or `none`)
- the accepted list intersects it
- negatives accept both `unknown` and `no_event`

The test reads the judge files; no model input does.

## Notes and proposals (not my paths)

1. **Shared vocabulary.** Put the coarse event classes in one contract file (for example `contracts/event_types.json`), read by P05's scripts, `inference/vocab.py` and the evaluation harness. Today they are mirrored and pinned by the data test.
2. **Stale fixture.** `data/fixtures/final_hypothesis.json` uses `traffic_obstruction_or_collision`, which is outside the new vocabulary. Its limitation text also differs from `NOT_DIRECTLY_VISIBLE`, so the gate appends the canonical one. Regenerate it per scenario with the live adapter.
3. **Fusion granularity (P04/P08).** With 8 frames 3.5 s apart, observations span several seconds, and single-linkage at `tolerance_s=1.5` put all 16 chain observations into one 28 s cluster. Denser sampling around candidate windows, or a cap on per-observation span, would give the reasoner sharper timing.
4. **Region set.** The region set is candidate ids plus `unknown`, the same as `submit_hypothesis`. Zone ids reach the reasoner only through fusion candidates (zone_prior / ray-in-zone).
