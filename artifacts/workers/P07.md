## Live adapter behaviour

- **Request.** The system prompt is followed by one user turn: a header with the valid frame indices, then for each frame a text label `Frame index=<i> t=<s>s` and a base64 JPEG data URL. Frames are downscaled to the profile's `max_image_width` (512 on lite and full).
  - `response_format` is a per-call JSON schema whose enums are the indices actually sent, the cue vocabulary, and the direction vocabulary plus null.
  - `reasoning_effort: "none"`.
- **Budget.**
  - `max_frames` (option, else the profile's media setting) is applied first, then a context-fit pass. The cost estimate is `ceil(w/32)*ceil(h/32)+2` tokens per image plus text at 3 chars/token.
  - The pass uniformly drops frames (keeping the first and last) until the prompt fits `context_tokens`, records the skipped indices, and fails cleanly if not even one frame fits.
  - Estimated against measured: about 2.2k estimated vs 2234-2272 measured prompt tokens for 8 frames at 512 px.
- **Post-processing (code, never trusted from the model).**
  - Tolerates code fences and prose, and accepts `{"observations": [...]}`, a bare list, another single list key, or one object.
  - Forces `camera_id` and drops citations of frames that were not sent.
  - An uncited item is mapped through its stated t-window, else dropped.
  - Times come from the cited frames' `t`. Cue types and directions are normalized; incident words become `other`.
  - Confidence is coerced: 85 becomes 0.85 and "high" becomes 0.8.
  - Dedupes on (cue, frames, direction) keeping the max confidence, and caps at 12 by confidence.
  - Ids are deterministic `<camera_id>.o<n>` in time order.
  - A description that names an incident is flagged in warnings, not rewritten.
- **Failure.** Invalid JSON gets one text-only repair turn (no images resent). A second failure, an endpoint error or an unfittable context gives an empty, schema-valid batch with `CallInfo.ok=False` plus the error. `strict=True` raises instead.

## Recalibration against the real data (important)

The first prompt asked for "reactions to an unseen cause", with incident-style cues (smoke, flash, debris, people scattering) and the line "ordinary activity is NOT a cue".

On real scenario_001 footage (MEVA G506/G436/G340) both models correctly returned `{"observations": []}`. That made the whole chain collapse to "insufficient". The reason is that the prepared scenarios' hidden events are drop-offs, pickups, turnarounds and stops in a blind pocket, and their visible evidence IS ordinary movement.

I inspected 8 uniformly sampled frames per model camera; the hidden clip was never opened. The cue vocabulary is now movement-based:

`vehicle_edge_transit, person_edge_transit, vehicle_slowing_or_stopping, vehicle_heading_change, vehicle_backing_or_maneuvering, person_vehicle_interaction, traffic_reaction, human_reaction, other`

Direction is redefined as the image side the cue points to: the edge a vehicle or person leaves through or arrives from. The prompt still forbids naming or guessing the unseen activity. Tests assert that the prompt contains no event-class name and no incident word, and that its cue block equals `CUE_TYPES`. Nothing downstream depends on specific cue strings: P08 and the web app pass them through.

## Observed model failure modes (handled in code)

- **Repetition loop (qwen3-vl:4b on cam_a).** It produced 8 near-identical "person walks right to left" items, each citing all 8 frames. Dedupe collapsed them to 1 (`dropped_items=7`). The prompt now asks for the 2 to 4 frames around a change, because a cue that spans the whole clip has no usable time for correlation.
- **Minor prompt non-compliance.** A parked SUV was reported as `other`, and `north` was used without a visible marking. Both are valid vocabulary, so they pass.

## Assumptions and notes

- `inspect_camera` checks the camera against the ModelScenarioView only when the caller passes `scenario_view`. The harness/agent tool binding should always pass it; it is the only thing the tool knows about the scenario.
- `data/fixtures/qwen_observations.json` (not mine) cites frames 8-10 at t 8-10.5 s, beyond an 8-frame manifest (indices 0-7). The fixture adapter warns and does not modify it. Recorded per-scenario fixtures (`data/fixtures/<scenario_id>/`) would fix this. The live adapter can produce them.
