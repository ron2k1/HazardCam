# P11 worker report: /ops live wiring

Status: done. Date: 2026-10-02.

`/ops` is now the live console: real API, SSE stream, and media, rendered by the existing prop-driven `OpsConsole`. The offline mock moved to `/ops?mock[=default|abstain|idle]`.

## Files

### New

- `apps/web/src/lib/api.ts`: typed client for `/healthz`, `/api/models/health`, `/api/scenarios`, `POST /api/runs` and `/api/judge/scenarios/{id}`.
  - `ApiError` carries status 0 for network or timeout failures.
  - Each request gets a 6 s `AbortSignal` timeout, `no-store` caching, and parsing of the FastAPI `detail` field (including the 422 array form).
- `apps/web/src/hooks/use-run-stream.ts`: one `EventSource` per run, held outside React state.
  - Every envelope goes through the existing pure reducer `applyEvent`, which drops `seq <= lastSeq`.
  - The client closes on `run.complete` / `run.failed`, so there is no reconnect loop.
  - While the browser is CONNECTING it reconnects natively and sends `Last-Event-ID`.
  - Once CLOSED, the hook reconnects itself with `?after_seq=N`: 5 tries, backoff from 750 ms doubling. After that the status is `lost` and the view becomes a failed run, `stream lost after N reconnects; server run state unknown`.
- `apps/web/src/hooks/use-stack-health.ts`:
  - Polls `/healthz` every 10 s, or every 4 s while offline.
  - Fetches `/api/models/health?profile=` only when the profile changes or the API comes back, never on a timer.
  - Derives online / degraded / offline / checking.
- `apps/web/src/components/ops/ops-live.tsx`: the live container (158 lines).
  - Loads scenarios and selects one. The `?scenario=` deep link is read on load and written on change.
  - Posts the run with profile `fixture` by default and optional `?pace=` (clamped 0..5).
  - The reveal is the only caller of the judge endpoint. A judge reply for another scenario is never shown.
  - Notices, in priority order: API OFFLINE, RUN REJECTED, SCENARIOS UNAVAILABLE, stream resuming.

## Assumptions

- **Profiles.** `/api/models/health` does not list profiles. The selector offers `fixture`, plus the API's own default profile from `/healthz` when that differs. In this setup that is `fixture` only, so nothing ever probes a model endpoint.
- **Scenario source.** The scenario object comes from the `GET /api/scenarios` list entry, which has the same shape as the public view. There is no extra `GET /api/scenarios/{id}`.
- **Deep links.** `?pace=` maps to `RunRequest.pace_s` for a slower, watchable demo; `?scenario=` preselects a scenario.
- **GT video controls.** The revealed GT `<video>` keeps the native `controls` it already had. They are browser-styled, the one non-HUD element on the page.
