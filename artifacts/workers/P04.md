## Sampling rule (full text in the `tools/sample_video.py` docstring)

1. The window is `[start_s, end)`, where `end = min(end_s, video end)`.
   - These raise `ValueError`: negative start, start at or past the end, `end_s <= start_s`, `sample_fps <= 0`, `max_frames < 1`, a NaN or inf value, or more than 1,000,000 candidates.
   - An `end_s` past the video end is clamped, and the clamped value is recorded.
2. The candidates are `t_k = start_s + k / sample_fps` for every k with `t_k < end`.
3. Each candidate maps to `frame_id = floor(t_k * src_fps)`, clamped to the last frame.
   - Duplicates (when `sample_fps > src_fps`, or after clamping) are dropped, keeping the first.
4. If more than `max_frames` remain, the sampler keeps positions `round_half_up(j * (n-1) / (max_frames-1))`.
   - First and last are always kept.
   - Spreading is applied to the unique frames, so oversampling still yields `min(max_frames, unique)` frames.
5. `t = frame_id / src_fps`, which is the exact frame start. `index` is the position in `frames[]`.
6. The arithmetic uses `Fraction(repr(x))`, so `start_s=0.29` at 100 fps is frame 29. Float arithmetic gives 28.999999999999996, which floors to 28. This replaces the `+1e-6` epsilon with exact math and yields the same result wherever the epsilon version was right.

## Video handling

- `src_fps` is `avg_frame_rate` when known, else `r_frame_rate`.
- **Constant frame rate (CFR) stream starting at time 0**: frames are picked by decoded frame number (`select=eq(n\,F)`), so `frame_id` is the literal source frame number.
- **Variable frame rate (VFR, `r_frame_rate != avg_frame_rate`) or a late-starting video stream (e.g. audio leads by at least half a frame)**: the stream is first conformed with `fps=src_fps:round=near:start_time=0`.
  - `frame_id` is then a slot on a constant `src_fps` grid.
  - Its JPEG is the source frame on screen at the slot midpoint, `(frame_id + 0.5) / src_fps`.
  - `t` stays an exact seek target on the media clock.
  - The tests show this is an identity on CFR (byte-identical JPEGs).
- **Rotation**: when display rotation is 90 or 270, the probe swaps width and height. ffmpeg autorotates the decoded frames, so JPEGs are upright.
- **Outputs**:
  - JPEGs go to `out_dir/<camera_id>/{index:04d}.jpg`, using `-q:v jpeg_quality` and `+bitexact`.
  - JPEGs are downscaled to `max_width` with aspect kept and even dimensions, and are never upscaled.
  - `clip=True` writes `clip.mp4` with H.264, yuv420p, `+faststart` and no audio.
  - The clip starts at `frames[0].frame_id` (clip t=0 is `frames[0].t` on the media clock) and holds `ceil((end - start_s) * src_fps)` frames, so its duration is within one frame of the window.
  - Stale frames and clips from earlier runs in that directory are removed. Other files are left alone.
- **Manifest**:
  - There are no wall-clock fields. `source_sha256` is the input file's SHA-256.
  - Paths are repo-relative POSIX inside the repo, else absolute POSIX.
  - The manifest is validated with `validate_json("media_manifest", ...)` before it is returned.

## Assumptions

- The media clock is the container timeline (what a browser's `currentTime` shows for mp4).
- For a frame-exact UI seek, target the middle of the frame, `t + 0.5 / src_fps`. A seek to exactly `t` lands on a frame boundary.
- `manifest.duration_s` is the video end on the media clock (the stream duration, plus the start offset for late-starting streams). `width`/`height` are the source display dimensions, not the JPEG dimensions.
- `sample_fps` records the requested candidate rate. When spreading applies, the spacing actually used is visible in `frames[].t`.
- Extraction decodes from frame 0 up to the last selected frame, which is exact and cheap for scenario-length clips. For a long source with a late window, cut a short prepared clip first (P05).
- Non-square pixels (SAR != 1) are not corrected.
