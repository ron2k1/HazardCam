## Files (mine)

- `inference/profiles.py`: `ModelProfile`, `EndpointConfig`, `MediaConfig`, `ProfileError`, `list_profiles()`, `load_profile(name=None, *, env=None, require_resolved=True)`.
  - The name comes from the argument, else `MODEL_PROFILE`, else `fixture`.
  - Env overrides `QWEN_BASE_URL/QWEN_MODEL` apply to perception and `MISTRAL_BASE_URL/MISTRAL_MODEL` to reasoning. They affect openai_compatible blocks only, and blank values are ignored.
  - An unknown profile raises an error that lists the available ones. Names are validated, so there is no path escape.
  - `REPLACE*` placeholders are fatal only for the selected profile.
- `inference/client.py`: the httpx `ChatClient`.
  - Timeouts are 10 s connect plus the profile `timeout_seconds`.
  - It retries with bounded exponential backoff (0.5 s doubling, 4 s cap) on 5xx, 408, 429, timeouts, transport errors, malformed bodies and EMPTY content. Other 4xx fail fast.
  - It strips leaked `<think>` blocks.
  - Logs carry the model, the attempt and the status code only: never the payload, images, the key or a response body beyond 200 chars of an error.
  - `extract_json()` handles fences and prose-wrapped JSON.
- `inference/base.py`:
  - Options: `PerceptionOptions`, `ReasoningOptions`.
  - Protocols: `PerceptionAdapter`, `ReasoningAdapter` (both runtime_checkable).
  - The `CallInfo` side channel, `AdapterError`, and `load_prompt()` (text plus a 12-hex sha256 version).
  - The factories `get_perception_adapter(profile)` / `get_reasoning_adapter(profile)`.
- `inference/health.py` (new, small): `check_endpoint(endpoint)` calls `GET <base_url>/models`, which Ollama /v1, vLLM and NIM all serve. It never raises. The live tests use it to skip, and the API can use it for the local-model health panel.
- `inference/frames.py`, `inference/coerce.py`: shared helpers (frame subset/labels/token estimate/JPEG encode; int/float/confidence coercion).
- `config/models/*.yaml` (5 profiles; currently gitignored, see BLOCKER):
  - `fixture`: no model calls. `fixture_dir: data/fixtures`; a per-scenario `<dir>/<scenario_id>/<file>` wins over the shared file.
  - `lite-local`: Ollama `http://127.0.0.1:11434/v1`, `qwen3-vl:4b-instruct` + `ministral-3:3b` (Q4_K_M), think off, json_schema, context 4096, perception images at most 512 px wide.
  - `full-local`: `qwen3.5:9b` + `ministral-3:8b`. The notes record that the 35B-class Qwen does not fit 8 GB VRAM, the thinking trap, and that qwen3.5 ignores json_schema.
  - `remote16gb`: base URLs are `REPLACE_FROM_ENV_*` placeholders, resolved by `QWEN_BASE_URL`/`MISTRAL_BASE_URL`.
  - `gb10`: ports 8000/8001, `model: REPLACE_ON_GB10` with the intended checkpoints in comments. Perception uses `think_param: chat_template_kwargs` (vLLM spelling) and reasoning uses `think_param: none`.

## Provider findings (probed live on Ollama 0.22.1, RTX 4060 8 GB)

- **Thinking toggle.** On `/v1`, only `reasoning_effort: "none"` disables thinking for qwen3.5. A bare `think: false` is silently ignored on `/v1`; it only works on native `/api/chat`.
  - Unset, qwen3.5:9b reasons first. Live: 96 max_tokens all went to 346 reasoning chars, giving empty content with finish=length.
  - With `reasoning_effort: "none"` it answered in 1.45 s with 0 reasoning chars.
  - The client treats empty content as retryable and the error names the thinking toggle. `reasoning_effort: "none"` is harmless for the non-thinking models (ministral, qwen3-vl).
- **Structured output.**
  - `response_format: json_schema` is honoured by ministral-3 and qwen3-vl.
  - qwen3.5:9b with thinking off ignores json_schema, json_object and native `format`, so prompt-instructed JSON plus post-validation carries it.
  - The grammar enforces enums but not number min/max (ministral returned confidence 92), hence the rescale and clamp in code.
- **Context.** `options.num_ctx` is ignored on `/v1`, and the loaded context is 4096. Ollama silently truncates oversized prompts: 12 frames at 768 px gave garbage. Profiles therefore carry `context_tokens`, and the perception adapter subsamples frames to fit and records it.
- **Event day (ARM64, vLLM/NIM).** All quirks are profile switches: `think`, `think_param` (`reasoning_effort` | `chat_template_kwargs` | `none`), `structured_output` (`json_schema` | `json_object` | `none`), `extra_body`, and `api_key_env` (env var NAME only; a validator rejects key-like values, and a test scans every YAML).

## Interface deviations (additive)

- `PerceptionOptions(scenario_id, scenario_view, max_frames, max_tokens, temperature, telemetry, strict)`, keyword-only. `ReasoningOptions(max_tokens, temperature, telemetry, strict)`.
- `CallInfo` side channel (latency, model, attempts, repaired, frames sent/skipped, dropped items, usage, finish reason, prompt version), delivered to `options.telemetry` and `adapter.last_call`. Contract objects never carry latency or model.
- Failures degrade to an empty batch or an abstention; `strict=True` raises `AdapterError` instead.
