## Results

Hypothesis: `passenger_dropoff_pickup`, `region_01`, confidence 0.75. The expected
answer is `passenger_dropoff_pickup` in `z_east_pocket`. The event type is right. The
region cannot be right: `z_east_pocket` lies outside every input camera's field of view
(see `artifacts/model/MODEL_BENCHMARK.md`), so no candidate region triangulated from the
visible cameras can match it.

The observations and the raw hypothesis are identical, field for field, to the
recording in `data/fixtures/eval_001/` (`qwen_observations.json`,
`final_hypothesis.json`). That recording was made from the same two models at
temperature 0 about two hours earlier (`provenance.json`, 14:37 UTC; this run 16:30
UTC). Greedy decoding with the same weights, prompts and sampled frames reproduces the
same output, so the match is expected. It is not a fallback: see the first acceptance
row.

## Limitations

- One scenario. Replaying all 22 lite-local recordings through the fixture eval scores
  decision 9/22, Brier 0.504 (`artifacts/model/MODEL_BENCHMARK.md`). This gate proves
  the app path, not model quality.
- Latency is a single run. After it, Ollama held only `ministral-3:3b` (4.64 GB VRAM),
  so the two models swap between perception and reasoning. cam_a took 8.4 s for 191
  tokens while cam_b took 9.2 s for 565, which suggests cam_a's call includes loading
  `qwen3-vl:4b-instruct`. The 22 lite-local recordings took 8.6-84.8 s each
  (`data/fixtures/*/provenance.json`).
- cam_c returned no observations (6 completion tokens). The model's own limitations
  text says so. cam_b's `dropped_items: 1` is a duplicate (same cue type, frames and
  direction) merged into an earlier observation; that path records no warning.
- Ollama serves a 4,096-token context by default and truncates silently. The profile
  downscales frames to 512 px and caps 8 frames per camera to fit; prompts here were
  2,251 and 2,553 tokens.
- The hypothesis panel scrolls at 1600 px wide, so the alternatives and limitations sit
  below the fold in the screenshots. No e2e assertion checks that they render yet; that
  is queued as a follow-up to the web worker.
